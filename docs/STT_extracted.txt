# LearnToday — Đặc tả & Trạng thái triển khai (Nguồn tham chiếu duy nhất)

> File này là bản tổng hợp giữa đặc tả gốc (STT.docx) và thực tế code đã có.
> Nguyên tắc từ giờ: khi làm 1 STT, code **đầy đủ mọi API liệt kê trong mục
> "API cần có"** ngay trong 1 lượt, không làm nửa vời rồi quay lại vá nhiều lần.
> Cập nhật cột Trạng thái + API thực tế mỗi khi hoàn thành thêm việc.

## STT 1 — Đăng ký tài khoản
**Trạng thái:** ✅ Hoàn thành

**Mô tả gốc:** Nhập Username, Email, Password → kiểm tra email chưa tồn tại →
mã hóa bcrypt (salt rounds = 10) → lưu database.

**API thực tế:**
- `POST /api/auth/register` — trả về `access_token`, `refresh_token`, `user`

---

## STT 2 — Đăng nhập
**Trạng thái:** 🟡 Gần xong — thiếu `/refresh-token` và `/logout`

**Mô tả gốc:** Xác thực Email+Password → cấp Access Token (1h) + Refresh
Token (7 ngày, lưu DB bảng `refresh_tokens`) → client tự làm mới AT qua
`/refresh-token` khi hết hạn → logout thì thu hồi RT trên server.

**API thực tế:**
- `POST /api/auth/login` ✅
- `POST /api/auth/forgot-password` ✅ (trả token trực tiếp, tạm thời chưa gửi email — chờ STT 13)
- `POST /api/auth/reset-password` ✅
- `GET /api/auth/me` ✅ (dùng `@token_required`)
- `PUT /api/auth/users/<user_id>/role` ✅ (cấp/thu hồi quyền admin, dùng `@admin_required`)

**API cần bổ sung (chưa làm):**
- `POST /api/auth/refresh-token` — nhận Refresh Token, kiểm tra hợp lệ + chưa bị `is_revoked` trong DB, cấp Access Token mới
- `POST /api/auth/logout` — set `is_revoked = true` cho Refresh Token trong DB

---

## STT 3 — Folder & từ vựng trong Folder
**Trạng thái:** ✅ Hoàn thành

**Mô tả gốc:** Phần A — CRUD folder (hệ thống do admin quản, cá nhân do user
quản). Phần B — xem từ trong folder, phân trang 20 từ/lần, tìm kiếm + lọc
theo từ loại/Level.

**API thực tế:**
- `GET /api/folders` — danh sách folder hệ thống + cá nhân
- `POST /api/folders` — tạo folder cá nhân
- `PUT /api/folders/<id>` — sửa (owner hoặc admin)
- `DELETE /api/folders/<id>` — xóa mềm (owner hoặc admin)
- `GET /api/folders/<id>/words?search=&word_type=&level=&page=&limit=` — phân trang + tìm kiếm + lọc
- `POST /api/folders/<id>/words` — thêm từ vào folder
- `DELETE /api/folders/<id>/words/<word_id>` — gỡ từ khỏi folder
- `POST /api/folders/system` — admin tạo folder hệ thống
- `PUT /api/folders/system/<id>` — admin sửa folder hệ thống
- `DELETE /api/folders/system/<id>` — admin xóa folder hệ thống

**Quyết định thiết kế đã chốt:** Admin có toàn quyền sửa/xóa cả folder cá
nhân của user khác (mục đích hỗ trợ), không chỉ folder hệ thống.

## STT 5 — Ôn tập từ vựng (SRS)
**Trạng thái:** ✅ Hoàn thành (routes/review.py, do người dùng tự code)

**Mô tả gốc:** Đếm từ có `next_review <= now`. Lấy đúng số từ theo cài đặt
`review_limit` (ưu tiên đến hạn sớm nhất), gọi Module 6.5 với `loại="review"`.
Nhận kết quả từng từ: `hoàn_thành` (tăng Level), `quay_về_lv1` (reset LV1),
`lùi_1_lv` (giảm 1 cấp), `bỏ_qua` (giữ nguyên). Kết thúc buổi hiển thị tổng hợp.

**API thực tế:** xem `app/routes/review.py` — cần đối chiếu lại chi tiết
endpoint khi làm tiếp phần frontend cho màn hình này.

## STT 6 — Học từ vựng mới (chu trình 5 từ)
**Trạng thái:** ✅ Hoàn thành (routes/learning.py, do người dùng tự code)

**Mô tả gốc:** Lấy từ LV0 trong 1 folder theo `daily_goal`. Gọi Module 6.5
với `loại="learn"`. Chỉ có kết quả `hoàn_thành` → gán LV1, `next_review = now
+ 20p`. Không có hộp thoại đề xuất/lùi LV/bỏ qua. Đạt mục tiêu ngày → cập
nhật streak, xét huy hiệu.

**API thực tế:** xem `app/routes/learning.py`.

## STT 6.5 — Module Quy trình học từ vựng (CỐT LÕI)
**Trạng thái:** ✅ Hoàn thành (`app/services/study_service.py`)

**Mô tả gốc:** Xử lý từng từ độc lập qua 4 bước: (1) hiển thị từ, (2) nhập
chính tả, (3) 3 dạng bài ngẫu nhiên (trắc nghiệm / điền từ có gợi ý / ghép
từ-nghĩa, đáp án sai lấy từ tối đa 4 từ còn lại cùng lô 5 từ), (4) tổng kết:
`learn` → luôn `hoàn_thành`; `review` → sai <4 lần thì `hoàn_thành` tăng
Level, sai ≥4 lần thì hỏi người dùng chọn 1 trong 3 (`quay_về_lv1` /
`lùi_1_lv` / `bỏ_qua`).

**API thực tế:** endpoint chấm điểm từng bước (`check-answer` — không cần
xác thực quyền sở hữu vì stateless, không ghi dữ liệu) — xem
`app/services/study_service.py` và route gọi tới nó.

## Ghi chú chung về hạ tầng đã có sẵn (dùng lại cho các STT sau)

- **Xác thực:** `@token_required` (bắt buộc đăng nhập), `@admin_required` (bắt buộc quyền admin) — trong `app/utils/middleware.py`
- **Chuẩn UUID:** mọi cột khóa chính/khóa ngoại dùng `db.String(36)`
- **Soft-delete:** chỉ áp dụng cho `words`, `folders` (cột `deleted_at`), không dùng cho bảng liên kết
- **Không dùng `ON DELETE CASCADE`** cho FK trỏ tới `words.id`/`folders.id`; có dùng CASCADE cho FK trỏ tới `users.id` ở các bảng phụ thuộc (`refresh_tokens`, `user_words`...)
- **Cache field** (`folders.word_count`, `users.streak`...): cập nhật ở tầng application, không dùng trigger DB
- **Migration:** dùng Flask-Migrate (`flask db migrate` / `flask db upgrade`), không sửa SQL tay trực tiếp trên Supabase nữa kể từ khi chuyển sang Flask-Migrate
